## 2. 決定 + 経緯
- 同期先は個人Google Driveの非公開 `AXIS_SYNC_PRIVATE` を継続使用する。
- 公開GitHubには以下を絶対に記録しない。
  - Google Sheet ID
  - Apps Script WebアプリURL
  - 同期token
  - 実顧客情報
- Apps Script WebアプリURL / token はAXIS端末のlocalStorageだけに保存する。
- Apps Script側にはtokenのSHA-256ハッシュだけをScript Propertiesへ保存する。
- 顧客・トレーニングデータはブラウザでAES-GCM暗号化してから送る。
- Apps Script / Google Drive側では平文の顧客データを扱わない。
- 同期先はappend-only encrypted snapshot方式を維持する。
- 複数端末で片方の記録を消さないため、単純上書きではなく pull → merge → push を維持する。
- draftは自動同期対象外。入力途中データは各端末ローカル優先。
- `data.enc` と `calendar.enc` は同期実装のために変更・再生成しない。
- Google Calendar予定を同期機能から直接削除しない。
- 自動同期を実顧客でONにする前に、普段使い端末へ設定し、完全JSONバックアップを取得してから初回同期する。

## 5. ハマり所
- Google Sheetsの「拡張機能 → Apps Script」はPlaywright DOM clickだとGoogle側UIレイヤーに阻害された。
  - Windowsの実Chromeへ `Alt + /` → `Apps Script` → Enter のキーボード操作で正常に開けた。
- Monacoエディタへ通常のpasteを行うと自動インデントが各行へ入り、Apps Scriptコードが破損した。
  - `window.monaco.editor.getModels()[0].setValue(source)` で直接セットすると元ファイルと完全一致で保存できた。
- 初回 `axisSetup` ではGoogle権限承認が必要。
- Webアプリデプロイ時にも追加のOAuth承認が必要だった。
- 「Google hasn’t verified this app」警告が出る場合がある。
  - 開発者と利用アカウントが同じ個人Googleアカウントであることを確認して承認する。
- Apps Script `ScriptApp.getService().getUrl()` はエディタ実行時に `/dev` URLを返すことがある。
  - `axisSetup` 再実行で `config.web_app_url` が `/dev` に戻る可能性がある。
  - 実運用で使うのはデプロイ管理画面に表示される `/exec` URL。
- `axisSetup` を今後再実行した場合は `config.web_app_url` を必ず確認する。
- 初期 `sync_state` に空のbootstrap行が残ると health の `snapshotCount` が1になる。
  - 空行削除後は `snapshotCount=0` を確認済み。
- 本番AXISのhealth接続確認は「自動操作用専用Chromeプロファイル」で実施した。
  - 普段使いWindows AXIS profileへURL/tokenが保存されたとはみなさない。
  - iPhone / Macにもまだ保存していない。
- 実API health / pullは確認済みだが、実顧客データのpushは未実施。
- 実顧客で自動同期をONにする前に完全JSONバックアップを必ず取得する。
- Service Workerの古いcacheで新JSが見えない場合がある。
  - ローカル検証は新規contextまたはSW無効、本番確認はSW有効で行う。
- `data.enc` / `calendar.enc` を同期作業中に変更しない。
- URL/tokenは秘密情報。画面ログ・PR本文・コミット・handoffへ値を記録しない。
