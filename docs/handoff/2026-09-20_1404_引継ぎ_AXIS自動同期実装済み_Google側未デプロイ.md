## 2. 決定 + 経緯
- 公開GitHubに個人Drive ID、Apps Script URL、同期トークン、実顧客情報を置かない。
- 静的GitHub Pagesから安全に書き込むため、個人Driveのbound Apps Script Web APIを使用する。
- 単純なlast-write-winsでは片端末の記録を消し得るため、append-only encrypted snapshot + pull/merge/pushを採用。
- Google Sheetsの1セル上限対策としてApps Script側で暗号payloadを40,000文字単位に分割保存する設計。
- 既存raw BASE / addedの顧客名は書き換えず、stable client ID + aliasesのoverlayを継続。
- 既存savedAtなし履歴は従来キーを維持し、既存の履歴編集を壊さない。
- `calendar.enc`は再生成しない。誤更新があった場合も新規生成せず、基準mainの元blobを復元する。

## 5. ハマり所
- Apps Script Webアプリの作成・デプロイはGoogle側でユーザー操作が必要。
- WebアプリURLや同期トークンをGitHubへコミットしない。
- Apps ScriptのGETはJSONP、POSTは`no-cors`フォーム送信後pullでchecksum確認する設計。
- `sync_state`既存`primary` bootstrap行は削除しない。Apps Scriptは`snapshot:<revision>:<part>/<count>`だけを読む。
- `config`は実ファイルで4列: key / value / description / updated_at。
- 既存savedAtなしセッションは履歴編集キーが旧ordinal方式。新規分のみ安定キー。
- Service Workerが古い場合があるので、本番確認ではcache-bustingとSW有効確認を行う。
- 自動同期を実顧客で有効にする前に実API E2Eを完了する。
- `calendar.enc`は今回一度誤更新された。今後、差分監査で必ずblob SHAを比較する。
